# URL Shortener Project Instructions

## Project

- Language: Go
- Module: `urlshortener`
- Entry point: `main.go`
- Database driver: `github.com/lib/pq`
- Database: PostgreSQL-compatible CockroachDB

## Development Commands

```bash
gofmt -w main.go
go test ./...
go vet ./...
go run .
```

Use `PORT` to select the HTTP port:

```bash
PORT=8081 go run .
```

`DATABASE_URL` is required to start the application. Set it in the shell or
load it from a local, untracked secrets file. Never commit the value.

```bash
export DATABASE_URL='postgresql://user:password@host:26257/database?sslmode=verify-full'
export PORT=8081
go run .
```

## API Routes

- `POST /shorten` — create a short URL from JSON `{ "url": "https://example.com" }`.
- `GET /urls` — list stored URLs; production implementations must paginate and protect this endpoint.
- `GET /{shortCode}` — look up a short code and redirect to the original URL.

Return HTTP `405 Method Not Allowed` for unsupported methods.

## Database and Secrets

- Read the database connection string from `DATABASE_URL` or a secret manager.
- Never hardcode credentials, tokens, or connection strings in source code.
- Do not log credentials or full connection strings.
- If a credential has ever been committed or shared, rotate it before deployment.
- Keep schema creation and migrations safe and repeatable.
- Use parameterized SQL queries and context-aware database calls.

## Production Requirements

- Do not claim support for 10,000 requests/second without representative load tests.
- Redirect traffic should use a cache such as Redis before querying the database.
- Configure database pool limits based on measured database capacity.
- Add request-size limits, URL validation, rate limiting, metrics, health checks, and graceful shutdown.
- Use HTTPS in deployed environments and do not construct public URLs from an untrusted `Host` header.
- Avoid unbounded queries or responses; paginate administrative/list endpoints.

## Coding Conventions

- Run `gofmt` on changed Go files.
- Preserve existing handler behavior unless the task explicitly changes the API.
- Use clear, small functions and return errors rather than silently ignoring them.
- Add tests for new handlers, validation, encoding/decoding, and database behavior where practical.
- After changes, run `go test ./...` and report any remaining failures.
